## Browser proof

`programme/proof/vite.config.mjs` is the authoritative local-only harness. The managed preview must mount a containing workspace with `core/` and the verified `pages/` source together, rather than mounting the nested proof folder. A containing Vite config can simply re-export `../core/programme/proof/vite.config.mjs`; the containing workspace supplies its Vite dependency. Set `SHIFT_PAGES_ROOT` when the verified Pages directory is elsewhere. The config now fails early if the pinned dashboard source is missing. This mount correction starts the preview successfully.

The harness creates only fictional Programme, free-tool and session records in `programme/proof/data/fictional.sqlite`. It cannot serve unrelated pages, real sign-in scripts or production APIs. Its `/member/dashboard` is a fixture landing screen, not a full rendering of the existing dashboard. The fixture selector and relaxed same-origin iframe policy belong only to this harness. The subsequent browser reload was rejected by browser URL policy; no alternate route or browser mechanism was tried. The current UI therefore has no new browser pass.

The deployable modules do not import Node SQLite, fixtures or the Vite harness. They use `env.PROGRAMME_DB`, the existing unchanged `authenticateMember` result and a single owner-scoped versioned aggregate. Every mutation uses one compare-and-swap statement so a write failure cannot leave a changed plan with an old shopping list. Retry operation identifiers are stored with their request signature.
