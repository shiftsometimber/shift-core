# Shift Core deployment toolchain

On 11 Aug 2026 Cloudflare Workers Builds failed before Worker compilation during automatic dependency installation. The floating `wrangler: ^4.0.0` range resolved into a dependency graph requesting unavailable `miniflare@5.20260804.1-alpha`.

## Production policy

- Node is pinned via `.nvmrc` to `22.16.0`, a Cloudflare-supported build runtime.
- The project package manager is explicitly declared as `npm@10.9.2`.
- Wrangler is pinned exactly to stable `4.112.0`; no caret/tilde/floating range is permitted for production deployment tooling.
- Prerelease markers (`alpha`, `beta`, `rc`, `nightly`, `canary`, `next`) are rejected by `toolchain-source-gate.mjs`.
- The Shift Master Integration Gate runs the toolchain source gate whenever the manifest/runtime/toolchain files change.

Cloudflare recommends project-local Wrangler so teams use a consistent version. Toolchain upgrades must therefore be intentional commissioning changes: update the pin, run CI/source gates, prove a Cloudflare preview/production build, then promote. Do not return to a broad Wrangler range merely to pick up a newer CLI automatically.

The repository did not previously contain a package-manager lockfile, so there was no lockfile to repair. The immediate deterministic boundary is the exact Wrangler pin plus explicit package-manager/runtime policy. If a lockfile is introduced later it must be generated by the declared package manager and committed in the same reviewed toolchain change; hand-authored or mixed-manager lockfiles are forbidden.
