# Pilot measurement pack
Prepared 28 September 2026. No real participants, results or recruitment created.

## Preserve distinct designs
Canonical existing protocol: 10–15 adults, eight weeks, activation-measurement/pilot-protocol.md.
Later growth proposal: 20 adults, four weeks, docs/growth-review/2026-09-27.md.
Do not silently replace either. Owner must select a design before recruitment. The definitions below make the four-week proposal reviewable without altering current analytics.

## Definitions
| Measure | Anchor and denominator | Numerator / interpretation |
|---|---|---|
| Proposed pilot activation | Recorded enrolment instant; all 20 visible | First saved check-in and Next Shift reached without facilitator help within 168 hours |
| Proposed first feedback | First issued action; all 20 enrolments reported plus number actually issued an action | First linked helped/not-fit/not-tried response within 168 hours of issue; skip/missing separate |
| Proposed week-four return | London enrolment date is day 1; only enrolments whose full day 28 ended enter mature rate | Retained check-in, explicit completed action or saved feedback on days 22–28; login alone excluded |
| Existing Continuity week one/four | First acknowledged visible Today, London days; full final window day ended | Existing saved meaningful-action definition unchanged; windows days 2–7 and 22–28 |
| Existing HQ week eight | Registration, 56 complete days eligibility; days 49–55 | Existing login/audited-save metric; cannot be relabelled useful return |
| Helpfulness | Distinct delivered episode; latest valid response | Helped / answered episodes; include not-fit and not-tried in answered; publish coverage separately; skip unanswered |

Proposed targets carried from the growth brief: 16/20 activation, 12/20 first feedback and 10/20 meaningful week-four return. These are proposals to freeze before recruitment, not observed results or authority to expand.
Report enrolled, due, not-yet-due, withdrawn, lost-to-follow-up, helped, not-fit, not-tried, skipped and unanswered counts. Include all 20 in cohort accounting; do not remove a non-returner to improve the rate. A zero mature denominator is not a zero-percent result.

Store this in the approved private operational system, not this repository. Do not put names, contact details, free health text or medicine details in analytics.
Optional separately consented category: treatment elsewhere / stopped / none / prefer not to say. Do not infer categories. Keep small subgroup results private; report counts and missingness without reidentification.

## Session and follow-up script
Start unaided from homepage. Ask: find what is useful to you, save one optional step, find it again, tell us whether it fits, and find help/privacy controls. Record assistance before giving it.
After task: What did you expect? What was confusing? What was useful? What would you change?
At weeks one/four (and eight only for eight-week design): What did you use without prompting? What did you stop using and why? Did the saved next step help? How much effort did returning take?
Ask no medication-change questions or clinical-outcome claims.

## Readiness and decision
Before recruitment: ordinary signup/inbox/security/reset proof; core consent/save/return checks; owner chooses protocol and operator; support capacity entered from operations worksheet.
After mature data: fix repeated task failures first; compare practical usefulness and return separately. Do not declare product expansion earned by passing software tests.
