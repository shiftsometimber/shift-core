This is a launch-quality inventory, not a count of theoretical AI combinations. Current production plan generation resolves through `member-product-v6 -> v5 -> v4`; therefore the V4 catalogues are the currently servable deterministic content base.

### Honest launch-ready count

Under the commissioning brief's full recipe standard, **0/16 are launch-ready today**. This does not mean the 16 are unusable; several are decent starter recipes. It means none currently satisfy the complete launch contract of validated nutrition + allergens + substitutions + storage/reheating/batch/food-safety metadata in a scalable content path.

### Variety failure

The current composer has only four choices in each meal type. It avoids repeats until each type is exhausted, then reuses the same pool. A normal unrestricted member therefore begins exact meal repetition on **day 5**. A dislike/Nay can make repetition arrive sooner. The endpoint also caps a request at seven days, so it cannot currently demonstrate 14/30/60-day catalogue variety as a single journey.

### V1 Grub launch floor

The floor is experience-led:
- Dave can run a 30-day plan without an exact lunch or dinner repeating inside 14 days.
- breakfast/snack repetition is allowed, but not more than once in a rolling seven-day window unless explicitly Yayed/favourited.
- at least 10 distinct dinner styles/cuisine families and meaningful protein-source diversity over 30 days.
- Nays/dislikes must leave enough safe alternatives that the diversity rule does not collapse.
- every surfaced item passes the complete recipe contract and semantic quality floor.

To provide the minimum inventory buffer for those constraints, the initial catalogue floor is **64 launch-ready recipes: 12 breakfast / 16 lunch / 24 dinner / 12 snack**. This number is a minimum derived from the repeat windows plus replacement headroom; the 30/60-day commissioning simulator may raise it if real plans still feel repetitive.

Current launch-ready: **0**. Initial deficit: **64**. Current raw recipe count: **16**; raw-count deficit to 64: **48**.

## Shift Fit — current production inventory

Current unique exercises: **12**:
- warm-up/mobility: 2
- legs: 2
- push: 2
- pull: 2
- core: 2
- cardio: 2

Location/equipment coverage is highly uneven. The base catalogue contains bodyweight/no-equipment movements plus one band row, one backpack row and one full-gym exercise-bike option. There is no meaningful dumbbell/full-gym movement library yet.

Current exercise properties:
- 12/12 have written instructions.
- 12/12 have time plus sets/reps where applicable; duration-based cardio/warm-up appropriately uses time rather than reps.
- 12/12 carry a rest value, although some duration movements correctly use zero.
- safety/form cues exist in the prose but are not a complete structured cue field.
- regressions/easier versions appear ad hoc in a few instruction blocks, not as a complete structured field.
- harder progressions are not defined per exercise; only a generic plan-level progression sentence exists.
- substitutions are generated by group replacement rather than explicitly modelled alternatives.
- limitation tagging is extremely thin: only a small number of exercises carry `avoid` tags.
- **0/12 have premium visual/illustrated guidance**.
- **12/12 remain embedded in Worker source**; the scalable `structured_content` repository exists but the live Fit composer does not consume it.

### Honest launch-ready count

Under the agreed rule that a member must never need to Google a prescribed movement, **0/12 are launch-ready today**, because visual guidance is absent and regression/progression/limitation metadata is incomplete.

### Session-variety failure

For a fixed context the composer takes the first eligible movement in each group. Repeated sessions for the same member/context therefore tend to reproduce the same exercise selection. More time adds additional movement groups rather than padding one exercise — that earlier dead-bug defect is fixed — but the catalogue is still far too small for a 12-week premium programme.

### V1 Fit launch floor

The experience floor is:
- Dave can train 3x/week for 12 weeks with purposeful progression, not random novelty and not the identical session every time.
- every major movement pattern has enough safe alternatives for location/equipment/limitation swaps.
- 10/15/20/30/45/60-minute sessions are physiologically coherent and materially different where time permits.
- home, gym, outside, hotel and work contexts have credible options.
- none/band/dumbbell/full-gym paths have credible coverage.
- every movement has clear visual guidance, instructions, dose, rest, safety/form cue, regression, progression and substitution metadata.

The initial floor is **48 launch-ready exercises with 48/48 visual guidance**, representing roughly six useful variants across eight core movement/mobility/cardio patterns and enough replacement headroom for common limitations/equipment contexts. The 12-week simulator may raise this if repetition remains poor.

Current launch-ready: **0**. Initial deficit: **48**. Current raw exercise count: **12**; raw-count deficit to 48: **36**. Visual-guidance deficit against the floor: **48**.
